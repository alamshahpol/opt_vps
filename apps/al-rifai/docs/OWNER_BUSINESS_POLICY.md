### Precise transport evidence — EXISTING IMPLEMENTATION and PROPOSED IMPLEMENTATION

**EXISTING IMPLEMENTATION, source-verified:** `services/whatsapp/source/whatsapp-bridge/main.go::sendWhatsAppMessage` calls `client.SendMessage` (1648); error returns false before success. On nil error it holds native `resp.ID` and `resp.Timestamp`, resolves the destination for storage and writes an outgoing row (1679), then returns true (1687). Native StoreMessage uses PK(id,chat_jid) and UPSERT. Paired account store determines account; direct chat determines peer; is_from_me and sender identify outbound self. Stored text/media timestamps are evidence, not a financial record.

**PROPOSED IMPLEMENTATION technical success predicate:** independently bound account=wa-01/paired …6111 + resolved approved Accountant direct peer …6824 + permitted Admin→Accountant direction + the transport SendMessage call returned without error, with nonempty native ID and timestamp linked to exact message payload/blocks. Capture that result durably with source/native event identity before posting/retry. Existing authenticated transport response `success:true` is corroborating call success only when the exact authorized call/account/destination/payload is attributable; HTTP 200, connection health, an attempted/queued request, “sent” text or synthetic bridge:recipient external ID alone is insufficient. Recipient delivery/read receipts and Accountant replies are not prerequisites.

**MISSING/UNVERIFIED technical details:** current SendMessageResponse (1167) exposes only success/message, not native stanza ID/timestamp.
